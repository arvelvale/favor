# Favor 冰箱优先重构方案（草案 v1，2026-11-17）

> 状态：方案已确认。第 1 期（核心闭环）已合入 master；第 2 期（问卷与偏好）在分支 `feat/preferences` 实现；第 3–5 期待做。每期独立 PR。

## 0. 已定的产品决策

| 决策 | 结论 |
|---|---|
| 目标 | 真的给人用（不是只为比赛/作品集） |
| 核心痛点 | 不知道冰箱里剩下的食材能做什么菜 |
| 主要用户 | 独居学生、上班族；给全家做饭的人也覆盖，由问卷区分 |
| 首次使用 | 先做问卷，按回答自动调整；之后是聚焦式、渐进的新手引导 |
| 健康模块 | 降为次要入口，保留不删 |

一句话定位：**冰箱里有什么，今晚就做什么。**

核心闭环：

```
录入食材 → 推荐菜（临期优先 · 缺料最少 · 合口味/厨具/时间）→ 做菜步骤
   ↑                                                          ↓
   └──── 做好了：自动扣库存 + 自动记一餐（健康数据成为副产品）───┘
```

差异化（通用 AI 聊天做不到或很麻烦的部分）：记住冰箱里有什么、临期食材优先、缺料最少、做完自动闭环。

## 1. 问卷：每题都必须改变一个看得见的东西

原则：
- 单屏一题，约 60 秒，最多 8 题；每题可跳过，跳过时用默认值，之后在合适时机再问
- **做不到「回答后立刻改变某个行为」的题目一律删掉**
- 最后一屏展示「根据你的回答，我们已经……」，逐条列出调整，每条都能点开修改
- 之后可以在「我的 → 偏好」里重做

| # | 问题 | 选项 | 自动调整什么 |
|---|---|---|---|
| Q1 | 你平时给几个人做饭？ | 只有我 / 两个人 / 一家人（再选：有老人、有小孩） | 默认份量；推荐结构（一人份优先「一锅出、少剩菜」；家庭优先「两菜一汤」搭配）；有老人小孩时提示少盐、软烂、儿童份量 |
| Q2 | 做饭水平？ | 几乎不会 / 会做家常菜 / 挺熟练 | 难度上限；步骤详细程度（新手会解释「焯水」「勾芡」等术语）；新手模式默认开启计时器 |
| Q3 | 工作日愿意花多久做饭？ | 15 分钟内 / 30 分钟左右 / 不赶时间 | 推荐的时间上限（超时的菜排后面并标注） |
| Q4 | 你有哪些厨具？（多选） | 炒锅 / 电饭煲 / 微波炉 / 空气炸锅 / 烤箱 / 只有一个小电锅 | **硬过滤**：没有烤箱就不推烤菜；「只有小电锅」走宿舍菜谱 |
| Q5 | 常备调料？（多选，默认勾选基础款） | 盐 油 酱油 醋 糖 / 蚝油 / 豆瓣酱 / 料酒 / 其他 | 勾选的调料不算「缺料」，避免每道菜都提示缺盐 |
| Q6 | 口味和忌口 | 辣度；不吃的（香菜、内脏…）；饮食方式（素食、清真…）；**过敏** | 过敏、饮食方式 = **硬约束，服务端校验**；口味 = 软偏好，影响排序 |
| Q7 | 你最想解决什么？（多选） | 不知道做什么 / 食材总放坏 / 想省钱 / 想吃得健康 / 想学做饭 | 排序权重和首页模块顺序；选「吃得健康」时把健康入口提到主导航并进入 Q8 |
| Q8 | （仅选了「吃得健康」时出现）目标与身体数据 | 减脂 / 增肌 / 保持；身高、体重等 | 复用现有档案与热量目标；推荐时按剩余热量约束 |

问卷结束后不直接进工作台，而是**无缝进入新手引导第 1 步**：「现在冰箱里有什么？」

## 2. 新手引导：聚焦式、渐进

原则：
- **聚焦**：每步只有一个目标，高亮唯一要操作的区域，其余区域变暗
- **做中学**：靠完成真实操作推进，不靠一路点「下一步」
- **渐进**：首次只讲核心闭环；其他功能等用户真正碰到时再提示（just-in-time）
- 任何一步都能跳过；进度存在服务端，换设备也能接着来

首次引导（目标：2 分钟内做出第一道「我现在就能做」的菜）：

| 步骤 | 聚焦区域 | 用户要做的事 | 完成条件 |
|---|---|---|---|
| 1 | 录入区 | 三选一：勾选常见食材 / 说一句话（「有鸡蛋、番茄、半颗洋葱」）/ 拍冰箱照片 | 库存里至少 3 样食材 |
| 2 | 第一张推荐卡 | 看懂卡片：用到哪些现有食材、缺什么、要多久 | 点开一道菜 |
| 3 | 做菜模式 | 按步骤做（可以点「今天不做，先收藏」） | 点「做好了」或收藏 |
| 4 | 完成提示 | 看到「已扣掉用掉的食材，并帮你记了一餐」 | 自动完成；顺带露出健康入口，不强推 |

之后的情境提示（每条只出现一次）：
- 第一次有食材临期 → 「快过期的会排在推荐前面」
- 第三次录入 → 「可以给食材设保质期，提醒会更准」
- 连续使用 3 天 → 「推荐会根据你做过、跳过的菜越来越合口味」
- 一周后（且未选健康）→ 轻提示健康模块

首页放一个「上手进度 2/5」清单卡，全部完成或手动关闭后消失。

## 3. 信息架构

| 现在 | 改为 |
|---|---|
| 总览（健康仪表盘） | **今天吃什么**（首页）：临期提醒 + 3 道推荐 + 库存摘要 |
| — | **冰箱**：库存管理（按冷藏/冷冻/常温分组，按临期排序） |
| 对话 | **对话**（保留，agent 能管库存、推荐、记录） |
| — | **收藏**：做过的、收藏的菜谱 |
| 趋势、记录 | 收进 **健康**（总览 + 趋势 + 记录 三合一，次要入口） |
| 档案 | **我的**：偏好（可重做问卷）+ 身体档案 |

健康入口的位置也由问卷决定：Q7 选了「吃得健康」放进主导航，否则放在「我的」里面。

落地页同步改版：主标题「冰箱里有什么，今晚就做什么」；演示动画改为「拍冰箱 → 识别食材 → 3 道推荐 → 做好了 → 自动记一餐」。

## 4. 数据与 agent

### 新增数据

- `pantry_items` 库存：名称、分类（蔬菜/肉/蛋奶/主食/调料…）、数量（**可选，不强制精确**）、单位、存放位置（冷藏/冷冻/常温）、加入时间、到期日（按分类给默认保质期估算并标注「估算」，用户可改）、状态（在用/用完/丢弃）、来源（拍照/文字/勾选/做菜扣减）
- `preferences` 偏好：问卷结果（JSON），注入 system prompt，并在服务端用于硬过滤
- `onboarding` 引导状态：当前步骤、已完成、已跳过的提示
- `saved_recipes` 收藏，`cook_logs` 做菜记录（做了哪道、何时、用掉什么）→ 用于自动记一餐和之后的口味学习

### 新增 agent 工具

`add_pantry_items` · `update_pantry_item` · `remove_pantry_items` · `list_pantry`（按临期排序）· `recognize_fridge_photo`（百炼视觉模型）· `recommend_recipes` · `mark_cooked`（扣库存 + 调用现有 log_meal）· `save_recipe`

### 关键工程约束

1. **硬约束在代码里校验，不只靠提示词**：过敏、饮食方式、厨具由服务端检查模型给出的菜谱，不合格的直接剔除或标警告
2. **缺料由服务端对照库存计算**，不信任模型自己说的「你都有」
3. **拍照识别结果先给用户确认再入库**，避免识别错误污染库存
4. 推荐的排序规则写成显式公式并写进测试（第 1 期已实现，见 `kitchen.rank_key`）：
   **现在就能做（不缺必需料）> 用到的临期食材多 > 缺料少 > 用到的库存多 > 耗时短**。
   实测后把「能不能马上做」提到第一位：缺料的菜再能消耗临期食材，也得先去买，不符合「剩下的能做什么」这个核心问题。
   第 2 期已接入问卷：不符合时间/难度/热量设置的菜排在「能马上做」之后、其余规则之前，并在卡片上标注原因；
   Q7 选「食材总放坏」时临期优先于是否符合设置，选「想省钱」时缺料少优先于临期（见 `kitchen.rank_key` 与 `tests/test_prefs.py`）。
5. 推荐和视觉识别每日限额，沿用生图的限额机制控制费用

### 复用

agent 框架、账号、对话、记录、热量目标、营养 RAG（回答「这道菜营养怎么样」）、菜品配图——全部保留。

## 5. 分期计划

| 期 | 内容 | 完成标准 |
|---|---|---|
| 1 核心闭环 | 库存表与工具；冰箱页（勾选 + 一句话录入）；推荐 + 做菜模式 + 做好了（扣库存、记一餐）；导航改版、健康降级 | 一个新账号能走完「录入 → 推荐 → 做好了」，库存和饮食记录正确变化 |
| 2 问卷与偏好 | 问卷 8 题；偏好注入；硬约束服务端过滤；「我们已经为你调整」总结页 | 不同问卷答案得到可见不同的推荐（有测试覆盖） |
| 3 新手引导 | 聚焦式 4 步引导；情境提示；上手进度清单 | 新用户 2 分钟内做出第一道菜（浏览器实测） |
| 4 降低录入成本 | 拍冰箱照片识别；落地页改版 | 拍照到确认入库 ≤ 3 次点击 |
| 5 越用越准 | 根据做过/跳过/收藏学习口味；临期提醒 | — |

引导放在第 3 期，因为它要带用户走的是第 1、2 期做出来的真实界面，界面先定型才能做引导。

## 6. 真实用户验证

第 1 期上线后，找 5–10 个独居的同学或同事用一周，看：
- 一周里做饭时，有几次是用 Favor 决定做什么的
- 第 7 天还在用的比例
- 录入一次库存平均花多久
- 他们最常抱怨的一件事

## 7. 风险

| 风险 | 对策 |
|---|---|
| 库存不准（吃了没扣、扔了没删） | 数量不强制精确；推荐前轻确认「这几样还在吗」；一键清点 |
| 被通用 AI 替代 | 差异化押在库存记忆、临期优先、做完闭环 |
| 推荐菜谱质量不稳定 | 服务端校验硬约束与缺料；收藏沉淀成自有菜谱库 |
| 调用成本 | 每日限额；推荐结果按库存变化缓存 |

## 8. 已确认（2026-11-17）

1. 菜谱由 AI 生成，服务端校验过敏原并对照库存计算缺料
2. 库存数量选填
3. 问卷可以整体跳过（每题也可跳过），跳过的用默认值

## 9. 第 2 期实现说明（2026-11-17）

- 问卷入口：新用户（及老用户第一次进来）进任意工作台页面前先到 `/welcome`；可整体跳过，也可逐题跳过，跳过的题用默认值并记录，供第 3 期的情境提示再问
- 题数：Q8 只在 Q7 选了「想吃得健康」时出现，所以大多数人是 7 题
- 硬约束（代码校验，`server/prefs.py`）：过敏（常见过敏原展开为具体食材，如「海鲜」→ 虾、蟹、贝…）、饮食方式、忌口、厨具。忌口和饮食方式命中「可省略」用料时只去掉该用料并标注，命中必需用料时整道剔除
- 过敏只存一处：健康档案的 `allergies`，问卷读写的就是它
- 「我的」页（`/app/me`）：列出每一题带来的调整，点任意一条单独修改，也可重做问卷
- 健康入口：选了「想吃得健康」进主导航（手机底栏替换「对话」，对话仍可从右下角按钮进入），否则在「我的」旁边
