# RAG 知识库语料规范

本目录存放**可溯源的营养学 / 医学科普要点**。检索时按文件切成片段，
只有带完整元数据的片段才会进入索引；含 `【待补充】` 的段落会被自动跳过。

## 一、每条文档必须有的 front-matter

```markdown
---
title: 准则三 多吃蔬果、奶类、全谷、大豆
source: 《中国居民膳食指南（2022）》平衡膳食八准则
publisher: 中国营养学会
published: 2022-04-26
url: https://dg.cnsoc.org/article/04/J4-AsD_DR3OLQMnHG0-jZA.html
evidence_level: 国家级学会指南
audience: 一般健康人群（通用科普）
tags: 蔬菜,水果,奶类,全谷物,大豆
---
```

| 字段 | 说明 |
|---|---|
| `title` | 片段标题，会显示在引用卡片上 |
| `source` | 原始资料名称（不要写「网上资料」这类模糊来源） |
| `publisher` | 发布机构，必须是可核实的机构名 |
| `published` | 发布日期，未知写「日期待核实」，不要猜 |
| `url` | 官方页面链接，必须真实可访问 |
| `evidence_level` | 证据等级：`国家级学会指南` / `政府公开文件` / `同行评议文献` / `科普整理` |
| `audience` | 适用人群；特殊人群资料必须单独标注 |
| `tags` | 逗号分隔的检索关键词 |

## 二、内容红线

1. **不整本复制**：只放自己整理的要点 + 出处链接，仓库是 public，避免版权风险。
2. **数值必须来自原文**：热量、克数、毫升、推荐摄入量等一律照录官方数值，不得推算或凭印象填写。
3. **缺项标 `【待补充】`**：没核实的结论宁可空着，代码会跳过这些段落，回答走「知识库暂无可靠依据」。
4. **不做诊断**：知识库只含科普与膳食指南，不含用药、剂量、治疗方案。
5. **特殊人群兜底**：涉及孕妇、婴幼儿、慢性病、过敏等提问时，系统在 Prompt 中强制追加「请咨询医生或临床营养师」。

## 五、如何新增 / 验证

1. 复制任一现有 md，改 front-matter 与正文要点；
2. 在 `server` 目录执行 `.venv/Scripts/python.exe -m rag.cli ingest` 做元数据体检；
3. 执行 `.venv/Scripts/python.exe -m rag.cli search "你准备验证的问题"` 看是否命中预期片段；
4. 在 `server` 目录执行 `.venv/Scripts/python.exe -m rag.evaluate --md rag/eval/report.md` 看成绩是否退化；
5. 在项目根目录执行 `.venv/Scripts/python.exe -m unittest discover -s tests` 跑全量回归测试。

## 六、英文食材检索词表

前端食材自动补全使用英文词，而语料是中文。`rag/glossary.py` 提供一份**纯词面**的
英中映射（例如 `tomato → 蔬菜 番茄`、`egg → 蛋类 鸡蛋`），检索前自动扩展查询；
文档的 `tags` 也会一并进入索引。该词表只做检索用词对应，**不含任何营养数值或健康结论**，
新增食材时在这里补一个词条即可，不需要改检索算法。
